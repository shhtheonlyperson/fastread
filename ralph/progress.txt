## Codebase Patterns
- Tests use `node --test` with `node:test` and `node:assert/strict` (.test.mjs files in `test/`).
- `src/article-extract.js` exports `extractArticle(html, sourceUrl)` returning `{ title, url, text, wordCount, source }`.
- `extractArticle` candidate `source` values: `entry-content`, `main`, `article`, `main-element`, `json-ld`, `body`, `none`. Plain-text input is not an HTML path; tests treat `.txt` separately and produce a synthetic `source: "plaintext"`.
- `countReadingUnits` (from `src/reader-core.js`) is the canonical word/CJK-unit counter. Use it for any token-count assertion.
- Class-based selectors recognized: `entry-content`, `wp-block-post-content`, `post-content`, `article-content`, `article__content`, `article-body`, `story-body` (priority 80, beats `<article>`/`<main>`).
- `src/url-ingest.js` exports `fetchAndExtract({ url, fetcher, maxBytes, signal })` plus typed error classes `InvalidURL`, `HttpError`, `OversizedError`, `UnsupportedContentType`, `TimeoutError`. Inject `fetcher` (defaults to `globalThis.fetch`) for unit testability — never call real network in tests.
- The Swift port (US-004) must mirror the same error taxonomy: invalidURL, httpError(Int), oversized, unsupportedContentType(String), timeout.
- Swift `ArticleLoader.fetch(urlString:session:maxBytes:)` lives in `Sources/FastReadCore/UrlIngest.swift` and accepts a `URLDataFetching`-conforming session (URLSession by default). Tests inject `URLSession(configuration: ephemeral)` with a `URLProtocol` stub.
- `Sources/FastReadCore/*.swift` files are compiled into both the SwiftPM `FastReadCore` library AND the FastReadApp Xcode target directly (not as a module dependency). When adding a new file under `Sources/FastReadCore/`, also add it to `FastRead.xcodeproj/project.pbxproj` in 4 places: PBXBuildFile, PBXFileReference, the FastReadCore PBXGroup children, and the FastRead PBXSourcesBuildPhase files list.
- Swift 6 strict concurrency: static mutable shared state in tests (e.g. URLProtocol stub handler) needs `nonisolated(unsafe)` plus an `NSLock` guard, since the test target compiles with concurrency checks on.
- `ReadingArticle` (Swift) lives in `Sources/FastReadCore/ReadingArticle.swift` as a `public` Codable struct with an explicit `public init`. The Xcode app target compiles it directly via pbxproj; FastReadApp call sites do NOT need `import FastReadCore`. Required (non-optional) fields: id, title, source, author, date, readTime, lede, tag, text, progress, wordIndex, timesOpened, isFinished. Optional date fields: sourceURL, createdAt, lastOpenedAt, finishedAt — older v0 JSON omits these.
- The JS persisted root shape (see `setItemAsync`/`getItemAsync` in `components/fast-read-screen.jsx`) is `{ library, articleId, wordIndex, wpm, ... }`: `wordIndex` and `isFinished`-equivalents live on the wrapper, not on each library item. Each library item itself uses `tagKey` (not `tag`).

  - `test/url-ingest.test.mjs` (new): 8 tests covering happy path, 404, content-length oversize, post-read oversize, application/pdf rejection, abort -> TimeoutError, non-http(s) URL (ftp/javascript), and ISO-8859-1 charset decoding fallback.

- `npm test` passes (36 tests; 8 new).
- **Learnings for future iterations:**
  - URL parsing must guard against schemes other than http(s) BEFORE the auto-prepend `https://`. A naïve `startsWith("http")` check lets `ftp://...` slip through and become `https://ftp://...`. Detect a leading scheme via `/^[a-z][a-z0-9+.-]*:/i` and only prepend when there is no scheme.
  - For decoding pages with non-utf-8 charset declarations, prefer reading via `arrayBuffer()` and using `TextDecoder(charset)` rather than `response.text()`. We fall back to ISO-8859-1 only when utf-8 decoding produces a U+FFFD replacement char.
  - The accept header / supported content-type regex is duplicated in JS and Swift. Keep them in sync when touching either side (US-004 will mirror this taxonomy in Swift).
  - Tests construct fake Response objects with `headers.get(name)` (case-insensitive), `ok`, `status`, `url`, `text()`, `arrayBuffer()`. Reuse this `makeResponse` helper pattern for any future ingest tests rather than pulling in `undici`/`msw`.
